MatMath

Framing a print? The window has to be smaller than the art by exactly the overlap, and the bottom border should ride a little heavier than the top or the whole thing looks off. Get every cut mark before the blade comes out.

Open MatMath

Exact cut marks

Window size, all four borders, and where each cut lands measured from the board edge. Millimeters or inches.

Optical centering

A dead-center window looks like it is sinking. Optical mode weights the bottom border, the way framers actually hang.

Mistake alarms

Print bigger than the frame, overlap eating the art, borders too thin to look right - flagged before you waste a board.

Drawn to scale

The board, the window and the print outline render to scale, so a wrong number looks wrong.

How the window works

The window is the print size minus the overlap on every side - the mat has to cover the edge of the paper or the art falls through. The borders are whatever is left of the frame opening. Optical centering splits the vertical border unevenly: top gets less, bottom gets more, by a weight you control (0.15 is a good default).

Checked by an independent implementation

The geometry engine (engine.js) runs in Node against a second implementation written in Python (tests/build_corpus.py). Both must agree on every window, border and cut mark across six frame scenarios. 72 checks pass (node tests/run_tests.js).
